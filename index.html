COMPLETED PROJECT

MediTrack

Enterprise Healthcare & Appointment Management Platform

Project Overview

SmartHealthcare is a full-stack web application that digitizes hospital appointment booking and patient record management. Built with a layered Spring Boot architecture and MySQL, it replaces manual scheduling with a system that enforces booking rules programmatically — eliminating double-bookings and giving administrators real-time visibility into doctor availability and patient activity. The system exposes both a REST API (JWT-secured, tested via Postman) and a server-rendered web interface (Thymeleaf), demonstrating two authentication strategies within a single, shared service layer.

Key Features & Functional Modules

  • Role-Based Access Control (RBAC): Two distinct roles — Patient and Admin — with separate dashboards and route-level authorization. Doctors are managed entities (added, edited, and scheduled by Admins), reflecting how hospital front-desk staff actually operate patient-facing systems..
  • Appointment Scheduling Engine: Real-time slot-conflict validation prevents a doctor from being double-booked for the same date and time; also enforces server-side rejection of past-date bookings, independent of client system clocks.
  • Medicine & Expense Tracking: Patients log recurring medications (with multi-timing support — e.g., a single entry for "Morning, Night") and track healthcare spending, with running totals computed via Java Streams..
  • Doctor Management (Admin): Full CRUD for doctor profiles — specialization, consultation fees, availability — with referential-integrity protection (a doctor with active appointments cannot be deleted until those are resolved).
  • Secure Authentication: BCrypt password hashing throughout; JWT-based stateless authentication for the REST API (verified with live token-required/token-rejected testing), and session-based authentication for the web dashboard, with server-side role verification independent of any client-side UI selection.

Techonlogies & Tools Used

Backend: Java 17, Spring Boot 3.x, Spring Data JPA, Hibernate
Security: Spring Security (Role Based), BCrypt Encryption
Frontend: HTML5, CSS3, JavaScript (ES6+), Thymeleaf Template Engine
Database: MySQL 8.0 (Relational Database)
Tools: Maven, Git, GitHub, Postman (API Testing)

Technical Challenges & Solutions

Double-booking prevention: Enforced repository-level slot validation (existsBy...) before write operations.

Handled DB Exceptions: Caught DataIntegrityViolationException to show clean UI messages instead of raw SQL traces.

Server-Side Security: Enforced backend date validation using the server clock to prevent client-side bypasses.

Secured Secrets: Migrated JWT keys and DB credentials from source code to environment variables.

Role Verification: Disregarded client UI toggles, verifying authorization solely via backend database roles.
